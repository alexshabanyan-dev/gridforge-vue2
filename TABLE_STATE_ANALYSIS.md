## Реализовано

### 1. Порядок колонок (column order)

- В `StoredTableState` хранится `columnOrder?: string[]`.
- При загрузке: merge с текущим набором колонок (удалённые убираем, новые — в конец).
- При drag-and-drop реордере — сохраняем обновлённый порядок.
- При сбросе — восстанавливаем порядок из `columns` (дефолт).

### 2. Дебаунс при ресайзе

- Запись в localStorage при ресайзе идёт через `persistTableStateDebounced` (400 ms).
- Мгновенная запись: смена видимости, «Сброс», окончание ресайза (`handleResizeEnd`), реордер (drop).
- При любом немедленном `persistTableState` отменяется запланированный debounce.

### 3. updateAutoMinSizes vs сохранённые ширины

- Добавлен параметр `skipWidthUpdateForColumnIds?: Set<string>` в `updateAutoMinSizes`.
- Для колонок из этого набора не перезаписываем ширину авто-минимумом (используются сохранённые значения).
- `storedColumnIds` заполняется из `mergeAndPersist` и передаётся в `updateAutoMinSizes`.

### 4. Обратная связь при сбросе

- Эмит `@reset` после сброса настроек.
- Краткая анимация `gf-table--reset-flash` (подсветка контура таблицы ~0.3 s).

### 5. Кнопка сброса при выключенном persist

- При `persistState: false` в меню настроек показывается «Сброс (только для этой сессии)».
- Сброс по-прежнему применяет дефолты к таблице, но не пишет в localStorage.

### 6. Сохранение pageSize, сортировка, getTableState

- **Storage:** в `StoredTableState` добавлены `pagination?: { pageSize, currentPage? }` и `sort?: SortState[]`.
- **Persist:** при `@page-size-change` — `persistPagination` (pageSize + currentPage 0); при `@page-change` (режим `pagination` с total) — обновляется `currentPage`; при `@sort-change` — `persistSort`. Всё только при `persistState === true`. Read‑modify‑write: колонки, pagination и sort не затирают друг друга.
- **Сброс:** «Сброс пользовательских настроек» сбрасывает и pagination (`pageSize` из пропа, `currentPage: 0`), и `sort` (пустой массив).
- **Доступ снаружи:** экспортируется **`getTableState(tableKey)`**. Родитель при маунте вызывает `getTableState(tableKey)`, читает `state.pagination?.pageSize`, `state.sort`, инициализирует свой state (в т.ч. для API-запросов), передаёт в таблицу как `pageSize` / `sortBy`. Таблица сама сохраняет при изменениях.

## Не реализовано

### 7. Версионирование и миграции storage

- Нет `version` в сохранённом состоянии.
- При добавлении новых полей возможны проблемы с обратной совместимостью.
- Идея: ввести `version`, при загрузке проверять и применять миграции.

### 8. Ошибки и квоты localStorage

- Ошибки записи (в т.ч. `QuotaExceeded`) тихо игнорируются.
- Идеи: `console.warn`, опциональный эмит `@persist-error` для уведомления пользователя.

### 9. Валидация и «битые» данные

- При невалидном JSON возвращаем `null` и идём по дефолтам.
- Можно усилить: проверять типы (`visible`, `width`), отбрасывать некорректные поля.

### 11. Визуальная индикация «есть сохранённое состояние»

- Нет явной индикации, что для таблицы что-то сохранено.
- Идея: подсветка иконки настроек/колонок или отдельная метка при наличии записи в storage.

### 12. Раздельное хранение по tableKey + смена ключа

- Разные таблицы различаются по `tableKey`.
- При смене ключа — новая «таблица» с нуля, без подсказок.
- Идея: документировать поведение; при необходимости — хелпер «скопировать состояние из ключа A в B».

## Текущее хранилище

- **Ключ:** `gf-table:{tableKey}`
- **Структура:** `{ columns, columnOrder?, pagination?: { pageSize, currentPage? }, sort?: SortState[] }`
- **Сохранение:** видимость и ширина колонок, порядок, пагинация, сортировка. Только сериализуемые данные.
- **Публичный API:** `getTableState(tableKey)` — загрузка состояния для инициализации `pageSize`, `sortBy` и т.д. снаружи (запросы к API).
